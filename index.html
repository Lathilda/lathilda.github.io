01  /  About

A lab that mostly builds the microscope

Lathilda is a small independent lab. We build instruments for data that has outgrown the tools built to look at it — and then we use them on real questions.

The unglamorous truth about large datasets is that nobody sees them. A scatter plot of ten million rows is either a solid black rectangle or a sample of forty thousand of them wearing a hat. So the standard move is to aggregate first and look second, which means every interesting thing that was smaller than the bucket you chose is gone before anyone looked.

Getting past that is only half a graphics problem. The other half is plumbing: formats, indexes, streaming, and deciding what not to load. We find this half genuinely interesting, which we accept is an unusual position.

We publish studies alongside the tools. Some use our engine. Some don't. The instruments exist to make questions answerable, not to be in every answer.

02  /  Product

Every analysis is a choice. Garden runs the ones you didn’t make.

A result is the product of a hundred small decisions — which controls, which window, which estimator, which outlier rule. Change one and the number moves. Garden runs the whole space and shows you the distribution instead of the single number you happened to land on.

Garden

Alpha · in development

Robustness analysis is a method everyone agrees with and almost nobody runs, because running it multiplies the compute by a thousand.

So we put it on the GPU and in the browser. Declare your model and the choices you could have made; Garden enumerates the space, executes it, and renders the result as a distribution you can interrogate — with no install and no cluster.

The method is domain-agnostic; analytical flexibility is not an economics problem. Economics is simply where we start, because it's where we have the data and the judgement to know when an answer is wrong.

03  /  Studies

Bounded questions that state what they failed to establish

Each study names one question, one substrate and one limit. Some use our own instruments. Some have nothing to do with them.

Study 001

Cascade Field

How local conditions and a handful of long-range links decide whether a small disturbance dies out or takes the whole field. Deterministic, replayable from its seed, and every run is a URL you can send to someone.

Limit — a synthetic rule system. It models no real contagion process and is not evidence about one.

In review Engine · interactive
Study 002

When overlapping windows invent predictability

On data with provably no signal, a random split of overlapping windows reports 66.0% accuracy against a 39.8% baseline. A purged split reports 32.9%. One analytical choice, two opposite conclusions — and a closed-form ceiling on how much accuracy the choice can manufacture.

Limit — synthetic order-book data. It says nothing about whether any real market is predictable.

Published No engine used
Study 003

Real-time macro, vintage by vintage

Reconstructing what was actually knowable at each historical moment, and asking how much published macro-finance survives being restricted to the data that existed at the time.

Limit — four euro-area series, frozen and hashed. No empirical finding claimed yet.

04  /  Engine

Where the boundary actually is

Interactive graph rendering in a browser plateaus around a hundred thousand nodes. Native tools reach millions. Closing that gap is a rendering problem, a layout problem and a data problem in roughly equal measure — which is why so few people work on all three.

Render

A WebGPU compute-and-render core. Typed state in, one draw call out. Verified bit-exact against its CPU reference at zero epsilon, so a result doesn't change when the hardware does.

WebGPU · f32 parity under fast-math

Pipeline

Formats, spatial indexes, chunked streaming and level of detail. The goal is simple to state and awkward to achieve: decouple how much data exists from how much has to be resident.

The half nobody demos

Layout

Force-directed layout falls over on high-degree nodes, where a single hub serialises the whole computation. That specific failure is the current object of study.

Open problem · in progress

05  /  Academy

Explaining the machinery, once it has earned it

Every mechanism we get working has to be explained twice: once in the precise vocabulary that lets a specialist check it, and once in plain language that is still true. If the two versions contradict each other, we don't understand it well enough to publish either.

The Academy is where the second version lives — written after the evidence is accepted, never as a substitute for it.
